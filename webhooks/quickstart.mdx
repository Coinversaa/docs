Five steps: an endpoint, a rule, a test event, a signature check, and the inbox. You need a **Starter** plan or above for the webhook channel and an API key from [developers.coinversa.ai](https://developers.coinversa.ai). Every request below goes to `https://backend.coinversa.ai/api/v1/webhooks` with your key in the `X-API-Key` header.

<Note>
No server? Skip the endpoint: write the rule with `{"kind":"inbox"}` and go straight to [step 5](#5-read-the-inbox), or let an agent do it — see [Webhooks for agents](/webhooks/agents).
</Note>

## 1. Create an endpoint

In the portal, open **Webhooks → Endpoints → Add endpoint**. Over REST:

```bash
curl -X POST https://backend.coinversa.ai/api/v1/webhooks/endpoints \
  -H "X-API-Key: $COINVERSA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/hooks/coinversa","description":"Production receiver"}'
```

`201 Created`:

```json
{
  "endpoint": {
    "id": "whe_01JC4QW7R3M8Z9X2K5N6P7Q8R9",
    "url": "https://example.com/hooks/coinversa",
    "description": "Production receiver",
    "status": "active",
    "allowInsecure": false,
    "consecutiveFailures": 0,
    "lastSuccessAt": null,
    "lastFailureAt": null,
    "disabledReason": null,
    "disabledAt": null,
    "probeAt": null,
    "probeCount": 0,
    "createdAt": "2026-11-03T14:00:00.000Z",
    "updatedAt": "2026-11-03T14:00:00.000Z",
    "createdVia": "api"
  },
  "secret": "whsec_/Im5PpCWQIZhaF0jeVnH3fmypIqQXqimytj1x9BGQEc="
}
```

<Warning>
The `secret` is shown **once**. Store it now — in your receiver's secret store, not in source control. If you lose it, [rotate](/webhooks/api#rotate-the-signing-secret) to get a new one.
</Warning>

The URL must be public `https`. Private, loopback and link-local addresses are refused with `url_rejected`, and redirects are never followed. For local development on **Agent** and above, set `"allowInsecure": true` to register an `http://` dev-tunnel URL (ngrok, localtunnel, Cloudflare quick tunnels).

## 2. Create a rule

A rule says which events you want and where they go. This one watches one wallet's BTC and ETH positions and its liquidations, and posts to the endpoint from step 1:

```bash
curl -X POST https://backend.coinversa.ai/api/v1/webhooks/rules \
  -H "X-API-Key: $COINVERSA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "label": "Whale 0x28f0 (BTC/ETH)",
    "eventTypes": ["wallet.position.opened", "wallet.position.closed", "wallet.position.flipped", "wallet.liquidated"],
    "filters": {
      "wallets": ["0x28f0d2a7c6b3e14f9a8b7c6d5e4f3a2b1c0d9bad"],
      "coins": ["BTC", "ETH"]
    },
    "channels": [{ "kind": "webhook", "endpointId": "whe_01JC4QW7R3M8Z9X2K5N6P7Q8R9" }],
    "cooldownMin": 1
  }'
```

`201 Created`:

```json
{
  "rule": {
    "id": "672f3b8e9d1c2a4b5e6f7a8b",
    "label": "Whale 0x28f0 (BTC/ETH)",
    "active": true,
    "eventTypes": ["wallet.position.opened", "wallet.position.closed", "wallet.position.flipped", "wallet.liquidated"],
    "filters": {
      "wallets": ["0x28f0d2a7c6b3e14f9a8b7c6d5e4f3a2b1c0d9bad"],
      "coins": ["BTC", "ETH"]
    },
    "channels": [{ "kind": "webhook", "endpointId": "whe_01JC4QW7R3M8Z9X2K5N6P7Q8R9" }],
    "cooldownMin": 1,
    "lastFiredAt": null,
    "firedCount": 0,
    "createdAt": "2026-11-03T14:01:00.000Z",
    "createdVia": "api"
  }
}
```

<Warning>
`cooldownMin` defaults to **0, which means fire once, then deactivate** — the behaviour of the original Telegram alerts. For a watch that keeps firing, set `cooldownMin` to the minimum number of minutes between fires.
</Warning>

Wallets are lowercase `0x` addresses, up to 1,000 per rule (your plan caps the total across rules). Retrying a create with the same body is safe: once the first attempt has saved the rule, the retry answers `409` with its `existing_rule_id` instead of creating a second one ([duplicates](/webhooks/api#create-a-rule)). Not sure how busy a wallet is? Send the same body to `POST /rules?dryRun=1` first: it validates the rule and returns `estimate.eventsPerDay` without saving anything, and a rule that would far outrun your plan is refused with `estimate_too_high` — see [estimate a rule before you save it](/webhooks/limits#estimate-a-rule-before-you-save-it). Coins use the canonical form — `BTC` for Hyperliquid perps, `xyz:GOLD` for builder dexes; omit `coins` for every coin. Each event type's filters are listed in the [event catalogue](/webhooks/events).

## 3. Send a test event

```bash
curl -X POST https://backend.coinversa.ai/api/v1/webhooks/endpoints/whe_01JC4QW7R3M8Z9X2K5N6P7Q8R9/test \
  -H "X-API-Key: $COINVERSA_API_KEY"
```

`202 Accepted`:

```json
{ "deliveryId": "dlv_01JC4QX2B7N4K8M3P6R9S2T5V8", "eventId": "evt_01JC4QW7R3M8Z9X2K5N6P7Q8R9" }
```

Your endpoint receives a `webhook.test` event, signed with the live secret:

```json
{
  "id": "evt_01JC4QW7R3M8Z9X2K5N6P7Q8R9",
  "type": "webhook.test",
  "version": 1,
  "occurredAt": "2026-11-03T14:21:07.890Z",
  "observedAt": "2026-11-03T14:21:08.412Z",
  "freshness": {
    "source": "synthetic",
    "typicalLagMs": 0
  },
  "rule": null,
  "summary": "Test event for endpoint whe_01JC4QW7R3M8Z9X2K5N6P7Q8R9. If you can read this, signature verification works.",
  "data": {
    "endpointId": "whe_01JC4QW7R3M8Z9X2K5N6P7Q8R9",
    "message": "This is a test event from Coinversa Pulse. Verify it with the Standard Webhooks headers webhook-id, webhook-timestamp and webhook-signature."
  },
  "context": {
    "suggestedTools": []
  },
  "disclaimer": "Descriptive market data from public on-chain activity. Not investment advice."
}
```

To exercise your handler with a realistic payload, send `{"type":"wallet.liquidated"}` (or any other type) as the body. The event is still a `webhook.test`; `data.sampleOf` names the type it imitates and `data.sample` carries that type's `data`. Check the result in the portal's activity log or with `GET /endpoints/{id}/deliveries`.

## 4. Verify the signature

Deliveries are signed the [Standard Webhooks](https://www.standardwebhooks.com) way: every POST carries `webhook-id`, `webhook-timestamp` and `webhook-signature: v1,<base64>`, an HMAC-SHA256 over `webhook-id + "." + webhook-timestamp + "." + rawBody` keyed with your decoded secret. A `standardwebhooks` library checks all of it. Verify against the **raw** request body — parsing and re-serialising the JSON changes the bytes.

```javascript Node (Express)
import express from "express";
import { Webhook } from "standardwebhooks"; // npm install standardwebhooks

const app = express();
const wh = new Webhook(process.env.COINVERSA_WEBHOOK_SECRET); // the whsec_… from step 1

app.post("/hooks/coinversa", express.raw({ type: "application/json" }), (req, res) => {
  let event;
  try {
    event = wh.verify(req.body.toString("utf8"), req.headers); // throws on a bad signature or stale timestamp
  } catch (err) {
    return res.status(400).send("bad signature");
  }
  // Deduplicate on event.id (also the webhook-id header), then hand off to a queue.
  res.sendStatus(200);
});
```

Python and Go libraries, dependency-free verifiers and a known-answer test vector are on [Signatures and delivery](/webhooks/signatures#verify-with-a-library). Answer quickly: anything slower than **5 seconds** counts as a failure and is retried.

## 5. Read the inbox

Every matched event is also kept in your inbox for your plan's retention window, whatever its channels:

```bash
curl "https://backend.coinversa.ai/api/v1/webhooks/events?limit=50" \
  -H "X-API-Key: $COINVERSA_API_KEY"
```

```json
        "suggestedTools": [
          {
            "tool": "pulse_trader_position_summary",
            "args": {
              "address": "0x28f0d2a7c6b3e14f9a8b7c6d5e4f3a2b1c0d9bad"

            "args": {

```

Event ids are ULIDs and sort by time. Save `nextCursor` and pass it back as `since` on the next call to get only newer events; `hasMore` says whether another page is ready now. Without `since`, the first call returns the last 24 hours. Filter with `types` (comma-separated) and `wallet`. If a response says `gap: true`, your cursor is older than what the inbox still holds — events may be missing, so re-read the state you depend on before carrying on ([the inbox gap flag](/webhooks/limits#the-inbox-gap-flag)).

## Pre-launch checklist

Before you point production traffic at a receiver, check each of these:

1. **Signature verified against the test vector.** Your verifier returns true for the [known-answer vector](/webhooks/signatures#known-answer-test-vector) with a fixed clock, and false when you change one byte of the body.
2. **Raw body.** The route reads the body as bytes before any JSON parser — `express.raw`, `request.body()`, `request.get_data()`, `io.ReadAll`.
3. **Clock in sync.** The receiver runs NTP; a clock more than 300 seconds off rejects every genuine delivery.
4. **Deduplicate on `webhook-id`.** Store processed ids for at least your retention window and skip repeats — retries and replays reuse the id.
5. **Answer in under 5 seconds.** Return `2xx` as soon as the event is verified and queued; do the work afterwards.
6. **Return `410` only on purpose.** It disables the endpoint at once and is never probed back.
7. **Both secrets during a rotation.** Your deploy can hold the old and the new secret for the 24-hour overlap, or accepts that either one verifies.
8. **Test every type you subscribe to.** `POST /endpoints/{id}/test` with `{"type":"…"}` for each, and check the delivery log shows `succeeded`.
9. **Dry-run every rule.** `POST /rules?dryRun=1` and compare `estimate.eventsPerDay` with your plan's monthly budget ÷ 30.
10. **Handle the notices.** Your code expects [`webhook.rate_limited`](/webhooks/events#webhook-rate_limited) and [`wallet.activity.digest`](/webhooks/events#wallet-activity-digest) and does not treat them as trades.
11. **Inbox as a backstop.** A scheduled job pulls `GET /events` from a saved cursor and handles `gap: true`, so an outage on your side costs you nothing inside the retention window.
12. **Watch endpoint health.** Alert on `status: "disabled"`, `disabledReason` and `probeAt` from `GET /endpoints`, or let `pulse_webhook_endpoints` tell you.

When something does go wrong, [Troubleshooting](/webhooks/troubleshooting) is ordered by symptom.
