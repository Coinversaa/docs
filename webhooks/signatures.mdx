Every webhook is a signed `POST` of one JSON event. Verify the signature, deduplicate on the event id, answer `2xx` within five seconds, and do the real work after you answer.

## The request

```http
POST /hooks/coinversa HTTP/1.1
Content-Type: application/json
User-Agent: Coinversa-Webhooks/1.0 (+https://docs.coinversa.ai/webhooks)
Coinversa-Event-Id: evt_01JC4QW7R3M8Z9X2K5N6P7Q8R9
Coinversa-Event-Type: wallet.position.opened
Coinversa-Delivery-Id: dlv_01JC4QX2B7N4K8M3P6R9S2T5V8
Coinversa-Attempt: 1
Coinversa-Signature: t=1762179668,v1=5f3a…
```

| Header | Meaning |
|---|---|
| `Coinversa-Signature` | `t=<unix seconds>,v1=<hex>` — the timestamp and one HMAC per active secret. During a [rotation](#rotating-the-secret) there are **two** `v1` values |
| `Coinversa-Event-Id` | The event id, `evt_` + a ULID. Stable across retries and replays; equal to `id` in the body. **Your idempotency key** |
| `Coinversa-Event-Type` | The event type, equal to `type` in the body |
| `Coinversa-Delivery-Id` | `dlv_` + a ULID identifying the delivery in your [delivery log](/webhooks/api#list-deliveries). A replay gets a new one |
| `Coinversa-Attempt` | `1` to `6` — which attempt of this delivery this is |
| `Coinversa-Replay` | `true` when you (or the portal) asked for this event to be sent again |

The body is the [event envelope](/webhooks/events#the-envelope).

## Verify a signature

The signed content is the timestamp, a literal `.`, and the **raw request body** exactly as received:

```text
signed_content = t + "." + raw_body
expected       = hex( HMAC-SHA256( key = your whsec_… secret, message = signed_content ) )
```

The key is the full secret string, `whsec_` prefix included, as UTF-8. A request is authentic when:

1. `t` is within **300 seconds** of your clock, in either direction — reject anything older to stop replayed captures, and
2. **any** `v1` value equals `expected`, compared in **constant time**.

Read the body as bytes before any JSON parser touches it; re-serialised JSON will not match.

<CodeGroup>

```javascript Node
import crypto from "node:crypto";

export function verifyCoinversaSignature(header, rawBody, secret, toleranceS = 300) {
  let t = null;
  const sigs = [];
  for (const part of header.split(",")) {
    const [key, value] = part.trim().split("=");
    if (key === "t") t = value;
    else if (key === "v1") sigs.push(value);
  }
  if (!t || !/^\d+$/.test(t) || sigs.length === 0) return false;
  if (Math.abs(Math.floor(Date.now() / 1000) - Number(t)) > toleranceS) return false;
  const expected = crypto.createHmac("sha256", secret).update(`${t}.${rawBody}`).digest();
  return sigs.some((sig) => {
    const got = Buffer.from(sig, "hex");
    return got.length === expected.length && crypto.timingSafeEqual(got, expected);
  });
}
```

```python Python
import hashlib
import hmac
import time


def verify_coinversa_signature(header: str, raw_body: bytes, secret: str, tolerance_s: int = 300) -> bool:
    t, sigs = None, []
    for part in header.split(","):
        key, _, value = part.strip().partition("=")
        if key == "t":
            t = value
        elif key == "v1":
            sigs.append(value)
    if not t or not t.isdigit() or not sigs:
        return False
    if abs(int(time.time()) - int(t)) > tolerance_s:
        return False
    expected = hmac.new(secret.encode(), t.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return any(hmac.compare_digest(expected, sig) for sig in sigs)
```

```go Go
package webhooks

import (
	"crypto/hmac"
	"crypto/sha256"
	"encoding/hex"
	"strconv"
	"strings"
	"time"
)

func VerifyCoinversaSignature(header string, rawBody []byte, secret string, tolerance time.Duration) bool {
	var ts string
	var sigs []string
	for _, part := range strings.Split(header, ",") {
		key, value, _ := strings.Cut(strings.TrimSpace(part), "=")
		switch key {
		case "t":
			ts = value
		case "v1":
			sigs = append(sigs, value)
		}
	}
	t, err := strconv.ParseInt(ts, 10, 64)
	if err != nil || len(sigs) == 0 {
		return false
	}
	if age := time.Since(time.Unix(t, 0)); age > tolerance || age < -tolerance {
		return false
	}
	mac := hmac.New(sha256.New, []byte(secret))
	mac.Write([]byte(ts + "."))
	mac.Write(rawBody)
	expected := mac.Sum(nil)
	for _, sig := range sigs {
		got, err := hex.DecodeString(sig)
		if err == nil && hmac.Equal(got, expected) {
			return true
		}
	}
	return false
}
```

</CodeGroup>

Call the Go version with `300*time.Second`. In Python frameworks, take the raw bytes (`await request.body()` in FastAPI/Starlette, `request.get_data()` in Flask); in Express, mount `express.raw({ type: "application/json" })` on the webhook route, as in the [quickstart](/webhooks/quickstart#4-verify-the-signature).

## Rotating the secret

`POST /endpoints/{id}/rotate-secret` returns a new secret, shown once, and `previousSecretExpiresAt` — **24 hours** later. Until then every delivery is signed with **both** secrets, so the header carries two `v1` values and a receiver holding either secret verifies. Deploy the new secret, then let the old one expire. The verifiers above already accept any matching `v1`.

## Success, failure and retries

A delivery **succeeds** on any `2xx` response within the timeout. Everything else is a failure: another status code, a timeout, a DNS failure, a refused connection, a redirect, or a URL that fails the address checks at send time.

| Attempt | Sent |
|---:|---|
| 1 | Immediately |
| 2 | 30 s after attempt 1 fails |
| 3 | 2 min later |
| 4 | 10 min later |
| 5 | 1 h later |
| 6 | 6 h later |

After the sixth failure — about 7 h 15 min after the first try — the delivery is **dead**. It stays in the delivery log for your plan's retention window, where you can replay it.

**One delivery per endpoint is in flight at a time**, so a slow endpoint only delays its own queue. Do not rely on order across events; sort by `occurredAt` (or by the time-sortable ULID in `id`) if order matters.

## Idempotency, retries and replays

Delivery is **at least once**: a timeout on our side after your handler succeeded produces a retry of an event you already have. Store each `Coinversa-Event-Id` you process and skip a repeat.

- A **retry** has the same event id and `Coinversa-Attempt` greater than `1`.
- A **replay** — `POST /deliveries/{id}/replay`, or **Replay** in the portal's activity log — has the same event id, a **new** delivery id, `Coinversa-Attempt: 1` and `Coinversa-Replay: true`.

## Timeouts and transport rules

- **5-second timeout** for connect plus response. Answer first, then process — push the event onto your own queue and return `200`.
- Only the first 1 KB of your response body is kept in the delivery log; there is no reason to send more.
- **No redirects.** A `3xx` is a failure; register the final URL.
- **HTTPS only.** On **Agent** and above an endpoint can set `allowInsecure` to use `http://` on a dev-tunnel host (ngrok, localtunnel, Cloudflare quick tunnels) for local development. Free and Starter cannot set it.
- The URL's host must resolve to public addresses only — loopback, private, link-local and cloud-metadata addresses are refused, both when you save the endpoint and before every attempt.

## Auto-disable

- A **`410 Gone`** response disables the endpoint immediately.
- After **20 consecutive dead deliveries**, or **72 hours** of failures with no success, the endpoint is disabled automatically and the account owner gets one email.

A disabled endpoint shows `status: "disabled"` with a `disabledReason`. Matching events keep landing in the [inbox](/webhooks/api#list-events) while it is off, so nothing is lost inside your retention window. Re-enable it with `PATCH /endpoints/{id}` and `{"status":"active"}` (or in the portal); re-enabling does **not** replay the missed events — pull them from the inbox or replay them one by one. To stop deliveries yourself without the failure count, set `{"status":"paused"}`.

## Rate limits on delivery

Your plan caps deliveries per minute and events per month ([Plan limits](/webhooks/limits)). Over the per-minute cap, the excess is not POSTed and you get one `webhook.rate_limited` event for that window; over the monthly budget, events are not POSTed either. In both cases the events remain in the inbox, marked `rate_limited` or `over_quota` in `deliveryStatus`.
