Seventeen event types. `webhook.test` and `webhook.rate_limited` are sent by us and cannot be put in a rule; `wallet.activity.digest` is what a rule receives instead of a wallet's individual events while that wallet is in [digest mode](/webhooks/limits#noisy-wallets-and-digest-mode). The machine-readable version of this page — same descriptions, plans, filters and samples, plus `filterDefinitions` describing every filter's type and bounds — is `GET https://backend.coinversa.ai/api/v1/webhooks/event-types`, which needs no key ([reference](/webhooks/api#list-event-types)). Its `subscribable` flag is authoritative for which types a rule may list.

Sample payloads are illustrative: addresses, hashes and amounts are made up, and every sample shares one `id` and timestamp pair.

## The envelope

Every event, on every channel — webhook body, inbox row, MCP result — has the same shape:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `evt_` + a ULID; time-sortable; also the `webhook-id` header |
| `type` | string | One of the types below |
| `version` | number | Schema version, `1` |
| `occurredAt` | ISO 8601 | The chain time of the fill or frame the event describes |
| `observedAt` | ISO 8601 | When Coinversa saw it |
| `freshness` | object | `source`, `typicalLagMs`, and `snapshotAt` for snapshot-based sources — see [freshness, per source](/webhooks/overview#freshness-per-source) |
| `rule` | object or null | `{ "id", "label" }` of the rule that matched; `null` for `webhook.*` events |
| `summary` | string | One descriptive sentence for an LLM or a human |
| `data` | object | The per-type payload, for code |
| `context` | object | `hyperliquidUrl` (when the event is about one coin) and `suggestedTools` — MCP tool calls, with arguments filled in, that answer the obvious next question |
| `disclaimer` | string | Always `"Descriptive market data from public on-chain activity. Not investment advice."` |

**Units.** Sizes and prices are decimal **strings** exactly as Hyperliquid emits them (`sz`, `px`, `avgPx`, `sizeBefore`); notional and PnL are **numbers** in USD (`notionalUsd`, `closedPnlUsd`). Sizes are signed where the field name says before/after — negative is short. Addresses are lowercase `0x` hex. Coins use the canonical form: `BTC` for Hyperliquid perps, `xyz:GOLD` for builder dexes.

## Rule filters

| Filter | Applies to | Meaning |
|---|---|---|
| `wallets` | every `wallet.*` type (required) | Lowercase addresses to watch; up to 1,000 per rule |
| `coins` | `wallet.*`, `market.liquidation.large`, `market.trade.large`, `cohort.bias_flipped` (required) | Canonical coins, up to 100. Omit for all coins, except on `cohort.bias_flipped`, which needs it: those are the coins polled |
| `minNotionalUsd` | `wallet.position.increased` / `.decreased` (default $50,000), `market.liquidation.large` (default $250,000), `market.trade.large` (default $250,000) | Minimum notional for the event to fire |
| `thresholdPct` | `wallet.liquidation_risk` | Fire when the distance from mark to liquidation price is at or below this percentage (0–100, default 10) |
| `price` | `market.price.crossed` | `{ "symbol", "target", "direction" }` — `direction` is `above`, `below` or `both` |

The same rules, as data, are the `filterDefinitions` object on [`GET /event-types`](/webhooks/api#list-event-types) — build a rule form or an agent prompt from it rather than from this table.

## Data fields

**Position events** (`wallet.position.*`): `wallet`, `coin`, `dex` (`hl` or the builder dex prefix), `change`, `side` (after the change; `flat` when closed), `sizeBefore`, `sizeAfter`, `notionalUsd` (size change times `avgPx`), `avgPx` (size-weighted over the coalesced fills), `closedPnlUsd` (sum of the fills' closed PnL), `fills` (how many fills were coalesced — all of one wallet's fills in a coin in one block become one event), `block`, `txHash` (of the last fill), and on `reconciled` only, `expectedSize`.

**Liquidation events** (`wallet.liquidated`, `market.liquidation.large`): `wallet` (the liquidated account), `liquidator`, `coin`, `side` (of the liquidated position), `sz`, `px`, `markPx`, `notionalUsd` (`px` times `sz`), `method`, `penaltyFeeUsd`, `closedPnlUsd`, `txHash`, `tid`. Fields Hyperliquid did not report are `null`.

**Liquidation risk** (`wallet.liquidation_risk`): `wallet`, `coin`, `side`, `sz`, `entryPx`, `markPx`, `liquidationPx`, `distancePct` (from mark to liquidation price; positive means still open), `thresholdPct`, `leverage`, `positionValueUsd`.

**TWAP fills** (`wallet.twap.filled`): `wallet`, `coin`, `twapId` (the Hyperliquid TWAP id), `sizeBase` (size filled in this block, in the coin), `notionalUsd`, `avgPx`, `fills` (slice fills coalesced — one wallet's slices of one TWAP in one block become one event), `block`.

**TWAP status** (`wallet.twap.status`): `wallet`, `coin`, `twapId`, `status` (as Hyperliquid reports it — `activated`, `waitingForTrigger`, `finished`, `terminated`, `stopped` — or `error`), `side`, `sizeBase` (the TWAP's total size), `executedSize`, `executedNotionalUsd`, `minutes`, `reduceOnly`, `randomize`, `description` (the node's reason when `status` is `error`).

**Activity digest** (`wallet.activity.digest`): `wallet`, `from` and `to` (the five-minute window covered), `suppressed` (how many `wallet.*` events were folded into it), `byType` (the count per event type), `notionalUsd` (summed over the folded events).

**Large trades** (`market.trade.large`): `wallet`, `coin`, `dex`, `side` (`buy` or `sell`), `positionEffect` (`open`, `increase`, `decrease`, `close` or `flip`, from the fills' direction), `sizeBase`, `notionalUsd` (Σ `px` × `sz` over the wallet's fills in the coin in that block), `avgPx`, `fills`, `block`, `txHash`.

**Price crossed** (`market.price.crossed`): `symbol`, `direction` (which way it crossed — `above` or `below`, also when the rule asked for `both`), `target`, `mid`, `prevMid`.

**Cohort bias flipped** (`cohort.bias_flipped`): `coin`, `cohort` (the PnL-tier slug, as `/live/cohort-bias/{coin}` returns it — see [cohorts](/concepts/cohorts)), `previousBias` and `bias` (net bias at the previous and the current poll; the sign changed between them), `longPct`, `shortPct`, `sampleSize`.

## `wallet.activity.digest`
