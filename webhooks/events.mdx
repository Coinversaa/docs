Twelve event types, in the order the API lists them. Ten are **subscribable** in a rule; `webhook.test` and `webhook.rate_limited` are sent by us. The machine-readable version of this page — same descriptions, plans, filters and samples — is `GET https://backend.coinversa.ai/api/v1/webhooks/event-types`, which needs no key.

Sample payloads are illustrative: addresses, hashes and amounts are made up, and every sample shares one `id` and timestamp pair.

## The envelope

Every event, on every channel — webhook body, inbox row, MCP result — has the same shape:

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `evt_` + a ULID; time-sortable; also the `Coinversa-Event-Id` header |
| `type` | string | One of the types below |
| `version` | number | Schema version, `1` |
| `occurredAt` | ISO 8601 | The chain time of the fill or frame the event describes |
| `observedAt` | ISO 8601 | When Coinversa saw it |
| `freshness` | object | `source`, `typicalLagMs`, and `snapshotAt` for snapshot-based sources — see [freshness, per source](/webhooks/overview#freshness-per-source) |
| `rule` | object or null | `{ "id", "label" }` of the rule that matched; `null` for `webhook.*` events |
| `summary` | string | One descriptive sentence for an LLM or a human |
| `data` | object | The per-type payload, for code |
| `context` | object | `hyperliquidUrl` (when the event is about one coin) and `suggestedTools` — MCP tool calls, with arguments filled in, that answer the obvious next question |
| `disclaimer` | string | Always `"Descriptive market data from public on-chain activity. Not investment advice."` |

**Units.** Sizes and prices are decimal **strings** exactly as Hyperliquid emits them (`sz`, `px`, `avgPx`, `sizeBefore`); notional and PnL are **numbers** in USD (`notionalUsd`, `closedPnlUsd`). Sizes are signed where the field name says before/after — negative is short. Addresses are lowercase `0x` hex. Coins use the canonical form: `BTC` for Hyperliquid perps, `xyz:GOLD` for builder dexes.

## Rule filters

| Filter | Applies to | Meaning |
|---|---|---|
| `wallets` | every `wallet.*` type (required) | Lowercase addresses to watch; up to 500 per rule |
| `coins` | `wallet.*`, `market.liquidation.large` | Canonical coins; omit for all |
| `minNotionalUsd` | `wallet.position.increased` / `.decreased` (default $50,000), `market.liquidation.large` (default $250,000) | Minimum notional for the event to fire |
| `thresholdPct` | `wallet.liquidation_risk` | Fire when the distance from mark to liquidation price is at or below this percentage |
| `price` | `market.price.crossed` | `{ "symbol", "target", "direction": "above" or "below" }` |

## Data fields

**Position events** (`wallet.position.*`): `wallet`, `coin`, `dex` (`hl` or the builder dex prefix), `change`, `side` (after the change; `flat` when closed), `sizeBefore`, `sizeAfter`, `notionalUsd` (size change times `avgPx`), `avgPx` (size-weighted over the coalesced fills), `closedPnlUsd` (sum of the fills' closed PnL), `fills` (how many fills were coalesced — all of one wallet's fills in a coin in one block become one event), `block`, `txHash` (of the last fill), and on `reconciled` only, `expectedSize`.

**Liquidation events** (`wallet.liquidated`, `market.liquidation.large`): `wallet` (the liquidated account), `liquidator`, `coin`, `side` (of the liquidated position), `sz`, `px`, `markPx`, `notionalUsd` (`px` times `sz`), `method`, `penaltyFeeUsd`, `closedPnlUsd`, `txHash`, `tid`. Fields Hyperliquid did not report are `null`.

**Liquidation risk** (`wallet.liquidation_risk`): `wallet`, `coin`, `side`, `sz`, `entryPx`, `markPx`, `liquidationPx`, `distancePct` (from mark to liquidation price; positive means still open), `thresholdPct`, `leverage`, `positionValueUsd`.

**Price crossed** (`market.price.crossed`): `symbol`, `direction`, `target`, `mid`, `prevMid`.
