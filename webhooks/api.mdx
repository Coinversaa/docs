Every route on this page is relative to one base URL and authenticated with your API key as a Bearer token:

```text
https://webhook.coinversa.ai
Authorization: Bearer YOUR_API_KEY
```

It is the same key as REST and the WebSocket. Subscriptions belong to the **account**, not to a particular key: any of your keys sees and manages all of them. The same operations are in the developer portal's **Webhooks** page and, for creating, listing and deleting, in the [MCP tools](/webhooks/agents#the-tools).

<Note>
This API is served by `webhook.coinversa.ai`, not the data API at `api.coinversa.ai`. It takes `Authorization: Bearer`, not `X-API-Key`, and it is not in the data API's OpenAPI spec. REST auth failures are `403` on the data API; here a missing or invalid key is `401`.
</Note>

## Summary

| Method | Path | Auth | What it does |
|---|---|---|---|
| `GET` | `/v1/subscriptions/definitions` | Bearer | The types your plan may create, with `args`, `filters` and `minTier` |
| `POST` | `/v1/subscriptions` | Bearer | Create a subscription; returns the signing secret |
| `GET` | `/v1/subscriptions` | Bearer | List this account's subscriptions (no secrets) |
| `DELETE` | `/v1/subscriptions` | Bearer | Delete **all** this account's subscriptions |
| `DELETE` | `/v1/subscriptions/{id}` | Bearer | Delete one subscription |
| `POST` | `/v1/subscriptions/{id}/enable` | Bearer | Re-enable a subscription a `410` disabled |
| `GET` | `/v1/subscriptions/{id}/secret` | Bearer | Read the subscription's signing secret |
| `GET` | `/health` | none | Service counts, or `503` |

## Definitions

`GET /v1/subscriptions/definitions` → `{ "types": [...], "filterLogic": "and" }`.

Only the types **permitted by your tier** are listed, so Free sees the Free-tier types even though its subscription allowance is zero: feed access and subscription allowance are separate checks. The same declarations drive validation and event field extraction — this is not an arbitrary query interface. Each type carries:

| Field | Meaning |
|---|---|
| `type` | The name you send at creation |
| `args` | Scope and configuration arguments. Each declares `type`, `required`, optional `options` and optional `default` |
| `filters` | Public field names. Each declares `type`, `label`, optional `unit` (`base` or `quote`), `exact`, optional enum `options` and the allowed numeric `operators` |
| `minTier` | The minimum plan, inherited from the underlying feed. `priceCross` also exports `sourceMinTiers` for its `mark` and `trade` sources |

```json
{
  "type": "tradesByUser",
  "args": {"user": {"type": "address", "required": true}},
  "filters": {
    "coin": {"type": "string", "label": "Market", "exact": true},
    "sz": {
      "type": "decimal", "label": "Size", "unit": "base",
      "exact": true, "operators": ["gt", "gte", "lt", "lte"]
    }
  },
  "minTier": "free"
}
```

The example omits the other trade fields for brevity. Read the endpoint rather than maintaining a client-side list.

## Create a subscription

`POST /v1/subscriptions`

| Body field | Type | Required | Notes |
|---|---|---|---|
| `type` | string | yes | One of the [six types](/webhooks/events) |
| `args` | object | per type | `user` for the four by-user types; `coin`, `threshold`, optional `source` and `direction` for `priceCross`; none for `liquidations`. Wallets are normalised to lowercase |
| `filters` | object | no | Exact values or `gt` / `gte` / `lt` / `lte` bounds, AND across fields — see [Filters](/webhooks/events#filters). `priceCross` takes none |
| `url` | string | yes | Public HTTPS on port 443. Redirects and private or reserved addresses are refused |

```json
{
  "type": "tradesByUser",
  "args": {"user": "0x0123456789012345678901234567890123456789"},
  "filters": {"coin": "BTC", "sz": {"gt": "1.5", "lte": "10"}},
  "url": "https://example.com/hook"
}
```

`args` selects and configures the source independently of the optional `filters`. The original top-level `user` spelling is still accepted, but do not send `user` both at the top level and inside `args`.

The response carries the subscription — `type`, the normalised `args`, the saved `filters`, its `id`, `url` and `disabled` status — and, **on creation only**, the `whsec_…` signing secret. List responses never include it; read it later with [`GET /v1/subscriptions/{id}/secret`](#read-the-signing-secret).

A subscription's configuration is **immutable**: delete and recreate to change it, which also resets `priceCross` crossing state. If activating the underlying feed fails, creation **rolls back** and answers `503` rather than leaving a saved subscription behind.

Errors: `400` (invalid format, unknown type, argument, filter or operator, impossible range — checked before anything is saved), `403` (the type is not permitted by your tier), `429` (your account is at its subscription allowance), `503` (auth, storage or feed unavailable).

| Type | `args` | Minimum plan |
|---|---|---|
| `tradesByUser` | required `user` | Free (Free's allowance is zero) |
| `twapSliceFillsByUser` | required `user` | Free (Free's allowance is zero) |
| `twapStatusesByUser` | required `user` | Pro |
| `liquidations` | none | Agent |
| `liquidationsByUser` | required `user` | Agent |
| `priceCross` | required `coin`, `threshold`; optional `source`, `direction` | Free for both sources (Free's allowance is zero) |

Tier checks are **creation-time** checks, not continuous re-authorisation of saved subscriptions after an account change.

## List subscriptions

`GET /v1/subscriptions` → this account's subscriptions, each with its `type`, `args`, `filters`, `id`, `url` and `disabled` status. No secrets.

## Delete a subscription

`DELETE /v1/subscriptions/{id}` deletes one subscription you own. For `priceCross` it also removes the crossing baseline and any pending deliveries in the outbox.

## Delete all subscriptions

`DELETE /v1/subscriptions` deletes every subscription on the account.

## Re-enable a subscription

`POST /v1/subscriptions/{id}/enable` re-enables a subscription that a `410` from your URL disabled. It is idempotent. It answers `429` if the account is already at its subscription allowance — a disabled subscription does not count toward it, so enabling one is a creation-time check again.

## Read the signing secret

`GET /v1/subscriptions/{id}/secret` returns the subscription's `whsec_…` signing secret — the one returned at creation. There is one secret per subscription and no rotation; see [Signatures and delivery](/webhooks/signatures#one-secret-per-subscription).

## Health

`GET /health` needs **no key**. It answers `{"subscriptions", "feeds", "queued", "retrying", "outbox"}` — counts of saved subscriptions, active feed subscriptions, queued fresh deliveries, waiting retries and pending outbox rows — or `503` if storage is unavailable.

## Delivery semantics

What a delivery looks like is on [Signatures and delivery](/webhooks/signatures). The status codes **your** URL returns mean:

| Your response | Effect |
|---|---|
| Any `2xx` | Acknowledged |
| `410` | The subscription is **disabled** until you call [`/enable`](#re-enable-a-subscription) |
| Anything else | Retried on the bounded policy — up to nine attempts over about 76 hours, respecting `Retry-After` up to 24 hours — then dropped |

## Errors

| Status | Meaning |
|---|---|
| `400` | Invalid format; unknown type, argument, filter or operator; impossible range. Nothing is saved |
| `401` | Missing or invalid API key |
| `403` | The source type is not permitted by your account tier (checked at creation) |
| `429` | The account's subscription allowance is reached — on create and on `/enable`. Disabled subscriptions do not count toward it |
| `503` | Auth, storage or feed unavailable. An unknown or missing auth tier fails closed. On create, the subscription was rolled back |

The tentative subscription allowances per plan are on [Plan limits](/webhooks/limits).
