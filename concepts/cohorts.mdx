---
title: "Trader cohorts"
description: "Every tracked wallet is classified by two independent tier systems: PnL and size."
---

Coinversa indexes every active Hyperliquid wallet and classifies it into two orthogonal tier systems:

- **PnL tier** — by all-time realized (closed) PnL from indexed fills
- **Size tier** — by lifetime traded notional (USD)

A classified wallet has exactly one PnL tier and one size tier. Wallets not yet in the traders rollup have no tier: cohort aggregates leave them out and say how many (e.g. `coverage.withoutTier`; `untracked` on builder cohorts). Together the two tiers form a 2D map of trader behavior — e.g. *"Sharps + Middleweights"* is a different cohort from *"Sharps + Featherweights"*, even though both are profitable.

Each tier has a canonical slug and a legacy slug. Requests accept either one on path parameters, query parameters and MCP tool arguments. Responses return the legacy slug (e.g. `pnlTier: "money_printer"`), so match on the legacy slug, or on either, when you read responses.

## All-time vs 30-day tiers

All-time tiers classify a wallet on its lifetime realized PnL and traded volume. 30-day tiers use the same slugs and the same dollar thresholds on the wallet's last 30 days (`pnl_tier_recent` / `size_tier_recent`), refreshed hourly. They are used by the `pulse_cohort_recent_*` tools / `/pulse/cohorts-recent/*` routes, and by `tierType=pnl_recent` on `live_positioning_by_entry` and `live_cohort_bias_history` (hourly `pnl_recent` snapshots from 2026-05-14).

Layer responses echo the axis as `cohortBasis` (`all_time_pnl`, `recent_30d_pnl` or `lifetime_volume`) and `tierWindowDays` (30, or `null` for all-time axes). Labels are always the wallet's *current* tier, so one wallet can sit in different cohorts on the two axes.

## How to query cohorts

Use the cohort tools when you want behavior at the group level rather than per wallet:

| Tool | Use it when… |
|------|--------------|
| `pulse_cohort_summary`           | You want every cohort's wallet count, total and average PnL, average win rate and total/average volume (all-time tiers). |
| `pulse_cohort_positions`         | You want to see what one cohort is currently long/short. |
| `pulse_cohort_trades`            | You want the recent trades from one cohort. |
| `pulse_cohort_history`           | You want how one cohort has performed over time. |
| `pulse_cohort_bias_history`      | You want a cohort's long-short bias trajectory. |
| `pulse_cohort_performance_daily` | You want day-by-day cohort PnL / volume. |
| `live_cohort_bias`               | You want who is long or short one coin right now, by tier (current snapshot). |
| `live_cohort_bias_history`       | You want hourly cohort-bias snapshots for one coin over up to 2160h (90d), with `tierType` `pnl`, `pnl_recent` or `size`, `tiers=apex,crowd` and `format=layer`. See [Cohort-bias history](/api-reference/chart-layers#cohort-bias-history). |
| `live_positioning_by_entry`      | You want one coin's open positions bucketed by entry price per cohort (snapshot only). See [Positioning by entry](/api-reference/chart-layers#positioning-by-entry). |
| `live_whale_trades`              | You want the largest fills by notional over up to 24h, with both counterparties' tiers. See [Whale trades](/api-reference/chart-layers#whale-trades). |
| `pulse_cohort_recent_positions` / `_trades` / `_lifecycle_stats` / `_top_positions` / `_alpha_concentration` | You want the same questions answered on 30-day tiers. |

Whale trades rank fills by size; they are unrelated to the Middleweights (legacy `whale`) size tier.

Cohorts are addressed by `tierType` (`pnl` or `size`) and `tier` (a slug from the tables above — either the new or the legacy slug works):

```
GET /pulse/cohorts/pnl/sharps/positions
GET /pulse/cohorts/size/middleweights/history
```

## When to use cohorts vs individual wallets

- **Cohorts** when you want a *signal* — "are the Middleweights loading up on BTC?" / "are the Sharps bearish on ETH?".
- **Builder cohorts** when you want the *user mix of a builder code* — the [builder endpoints](/api-reference/builders) label wallets with their **lifetime** tiers (`pnlTier` / `sizeTier`, legacy slugs), which can differ from the 30d-rolling tiers the `cohorts-recent` endpoints classify by. See [Builder codes & attribution](/concepts/builder-attribution#cohort-tiers-on-builder-endpoints).
- **Individual wallets** when you want a *specific story* — "what is `0xabc...` doing?" / "how is this trader I follow performing?".

Most agent workflows benefit from cohort-first analysis: it's signal-rich, and you can drill into specific wallets with `pulse_token_leaderboard` (top traders for a coin) when you want names.
